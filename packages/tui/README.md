# @ji.dev/tui

**English** · [简体中文](README.zh-CN.md)

The parts of a full-screen terminal chat, none of them knowing what is said in it. [`apps/coding-agent`](../../apps/coding-agent) is built on it: it decides what the bars say and how a reply reads, and leaves the drawing here.

```ts
import {
  createRailRows,
  createRuleElement,
  createTextElement,
  Markdown,
  Screen,
  stackVertically,
  widthBesideRail,
} from '@ji.dev/tui'

const screen: Screen = new Screen(() =>
  stackVertically([
    createTextElement(['', ' my app']),
    createRuleElement([]),
    screen.content,
    createTextElement(' › '),
  ]),
)
screen.start()
const markdown = new Markdown(createRailRows(process.stdout, '│'), widthBesideRail)
await markdown.write('# Hello\n\nSome **bold** text\n')
markdown.end()
```

To the program, stdout is the content element: it is written to a headless terminal whose `columns` and `rows` are the content's size, so [clack](https://bomb.sh/docs/clack/basics/getting-started/)'s output and prompts work unchanged. The brief and the full view are a headless terminal each, both written to, so switching views needs no replay. The screen takes over the process's stdout, so there is one at a time.
