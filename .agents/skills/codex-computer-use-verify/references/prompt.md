# Prompt 模板

## 首轮验证

```text
请用 Computer Use 操作已经打开的 "<应用名>" 应用（bundle id <bundle id>），验证<功能>。
只操作 <应用名>，不要运行 shell 命令，不要修改任何文件，不要给模型发送普通消息，不要点 /exit。
系统当前是<深色/浅色>外观，这是正常的。

先<进入被测状态，例如：选中左侧任意一个已有会话；没有就新建一个>。然后按顺序做下面每一步，
每步截图观察，汇报 PASS 或 FAIL 以及你实际看到的内容：

1. <操作>。期望：<看得见的结果，写具体文字、位置、颜色、计数>。
2. ...
N. <涉及凭据的步骤>：在 key 输入框里输入 "abc"，期望显示成圆点；然后点 Dismiss，不要提交。

全部做完后给出汇总表：每步 PASS/FAIL，以及任何视觉问题
（重叠、截断、颜色不可读、对齐错位、浮层被裁剪）。
```

## 复查（只写失败项）

```text
请用 Computer Use 操作已经打开的 "<应用名>"，复查 <n> 处。（同样的限制：……）

1. <原来失败的那一步>。期望：<修复后应该看到的结果>。
2. <上次没验到的步骤，这次写明具体选项>：选 deepseek；没有的话选任意一个 API key 类 provider。

最后给出每步 PASS/FAIL 汇总。
```

## 写期望时注意

- 写能看到的具体东西："状态栏显示 `1 of N`"、"/think 排第一，`th` 带下划线"。不要写"菜单正常"。
- 一步只验一件事，按键操作写明次数（"按两次 ↓，再按一次 ↑"）。
- 每步结束时把界面恢复原状（Esc、清空输入框），免得影响下一步。
- 要求 Codex 顺带报告视觉问题。它常能发现期望里没写到的问题，比如文字被截得太短。
