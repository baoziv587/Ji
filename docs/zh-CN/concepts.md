# 核心概念

[English](../concepts.md) · **简体中文** · [文档导航](README.md)

用最直白的方式讲 JI 怎么工作。发第一条消息用不到这些；想知道一次运行为什么这样推进，或者准备写插件之前，读一读会有帮助。

<br>

## 四个对象

| 对象    | 是什么                                                  | 创建方式               |
| ------- | ------------------------------------------------------- | ---------------------- |
| Agent   | 配置：用哪个模型、哪些工具、哪些插件。建一次，反复用    | `createAgent(...)`     |
| Session | 一段对话。保存历史，以及还没送达的消息                  | `createSession(agent)` |
| Run     | 为一条消息做的全部工作，直到 agent 回答完。可以边跑边读 | `chat.send(...)`       |
| Plugin  | 你自己的代码，在 agent 工作的固定位置被调用             | `definePlugin(...)`    |

```ts
const agent = createAgent({ model, tools: [calculator] }) // Agent
const chat = createSession(agent) // Session
const r = chat.send('17 × 23 等于多少？') // Run
console.log(await r.result)
```

<br>

## 从一条消息看循环

agent 按**步**工作。上面那条消息会经历：

1. **写入你的消息**：消息加入历史。
2. **模型要用工具**：它想用计算器。JI 执行工具，得到 `391`，把模型的请求和工具结果一起加入历史。
3. **模型回答**：它读到 `391`，直接回答，不再调用工具，回答加入历史。
4. **运行结束**：模型已经回答，也没有等待送达的消息，没有事要做了。

每一步做两件事之一，然后把结果保存下来：

```text
有等待的消息？  有   → 加入历史
                没有 → 调用模型，再执行它要的工具
把这一步写入历史，然后开始下一步
模型不再调用工具、直接回答时停下
```

一次运行可能只有一步，也可能有很多步。调用哪些工具、什么时候结束，由模型决定。`maxSteps` 限制步数，运行不会无限循环（见 [上限](sessions-and-runs.md#上限)）。

<br>

## agent 忙的时候发消息

运行还在进行时，你可以继续发消息。它会并入同一次运行，而不是另起一次。送达时机由你选：回答完之后、当前这一步之后，或者立即送达并取消正在进行的这一步（见 [运行中插话](sessions-and-runs.md#在-agent-工作时插话)）。

被取消的那一步会整个丢弃，不会写入历史，所以对话里永远不会出现半步。

<br>

## 插件放在哪里

插件挂在循环里有名字的位置上，这些位置叫**钩子**。几个例子：

| 你想做的事             | 钩子       | 什么时候运行           |
| ---------------------- | ---------- | ---------------------- |
| 给请求补充检索到的资料 | `request`  | 每次调用模型之前       |
| 缩短过长的工具结果     | `toolCall` | 包住每次工具调用       |
| 历史太长时写摘要       | `decide`   | 每一步开始时           |
| 记录日志或链路追踪     | `observe`  | 每个事件都会收到，只读 |

[编写插件](plugins.md) 列出了全部钩子，以及它们在一步里的位置。

<br>

## 保存了什么

会话的状态是普通 JSON：消息，加上每个插件自己的数据。用 `JSON.stringify(chat.state)` 保存，之后传回 `createSession` 就能继续（见 [保存与恢复](sessions-and-runs.md#保存与恢复)）。

状态只在一步完成后才会改变。运行失败或被取消时，你手里仍是最后一个完成步骤的状态，可以从那里继续。

<br>

## 深入了解

用 JI 开发不需要下面这些。如果你好奇循环是怎么搭起来的：

- [agent loop](plugins.md#agent-loop)：逐个钩子拆开一步，以及每一步记录的 turn 种类
- [内核 API](kernel.md)：所有 agent 都由三个函数构成，以及建在它们之上的几层
